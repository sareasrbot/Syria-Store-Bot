# مشروع سوريا ستور

## الملفات
- `main.py`: كود البوت.
- `requirements.txt`: المكتبات.
- `render.yaml`: إعداد خدمة Render وقرص دائم لقاعدة البيانات.

## متغيرات Render المطلوبة
- `TELEGRAM_BOT_TOKEN`: توكن بوت تلغرام.
- `GUNES_API_TOKEN`: مفتاح Gunes API.
- `RENDER_EXTERNAL_URL`: رابط خدمة Render.
- `ADMIN_TELEGRAM_ID`: مضبوط افتراضياً على 8214089375.
- `DB_PATH`: مضبوط على `/var/data/syria_store.db`.
- `STORE_MARKUP_PERCENT`: نسبة الربح الافتراضية 10%.
- `SUPPORT_TEXT`: رسالة خدمة العملاء (اختياري).
- `TELEGRAM_WEBHOOK_SECRET`: سر حماية webhook (اختياري).

## إعداد طرق الدفع
بعد تشغيل البوت، من حساب المدير أرسل:
`/setpayment شام كاش | أرسل المبلغ إلى رقم ... ثم أرسل صورة الإيصال`
`/setpayment USDT Binance | أرسل إلى عنوان المحفظة ... ثم أرسل صورة التحويل`
`/setpayment سيريتل كاش | أرسل إلى الرقم ...`
`/setpayment تحويل بنكي | بيانات الحساب ...`

تعطيل طريقة دفع:
`/disablepayment 1`

تعديل نسبة الربح:
`/setmarkup 10`

إضافة رصيد يدوياً:
`/addbalance TELEGRAM_ID 5`

## ملاحظات مهمة قبل التشغيل التجاري
1. قاعدة البيانات SQLite محفوظة على Render Persistent Disk تحت `/var/data`.
2. يجب أن تكون الخدمة على Render بخطة تدعم Persistent Disk. إذا كانت خطتك لا تدعم القرص الدائم، استخدم PostgreSQL أو ترقية مناسبة قبل استقبال أرصدة حقيقية.
3. وثائق Gunes توضح أن `newOrder` يستخدم GET و `qty` و `order_uuid`، و`playerId` عند الحاجة. الحقول الإضافية ترسل في الكود باسم `param2`, `param3` مؤقتاً؛ يجب تأكيد أسماء مفاتيح أي منتج متعدد الحقول مع Gunes قبل تفعيله.
4. طلبات Gunes بحالة `wait` أو نتيجة اتصال غير مؤكدة تبقى محجوزة ولا يعاد رصيدها تلقائياً. يجب مراجعتها من لوحة Gunes قبل التسوية.
5. لم يتم تنفيذ اختبار شراء حقيقي أو تحويل مالي. اختبر أولاً بمنتج تجريبي وبمبلغ صغير بعد التأكد من بيانات الحقول.
6. الصور: يستخدم البوت روابط الصور المباشرة، و`category_img` إذا كانت مسار صورة.
7. لا تشارك مفاتيح API أو توكن البوت مع أي شخص.
